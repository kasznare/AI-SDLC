01 / THE CHALLENGE

From individual use
to working as a team.

A developer may already be working faster with AI. Across the team, review workloads can still grow, knowledge can become fragmented, and actual costs can remain invisible.

Adoption means addressing the whole workflow: where AI gets its context, what it can do on its own, who reviews its work, and how we know whether it was worthwhile.

Add tools where there is a clear need.

We build on existing AI subscriptions, development tools and internal systems. We choose a new product when a specific access, integration or operational requirement calls for it.

The formula and total budget

Monthly runs = developers × daily tasks × workdays × runs/task.

Token cost = monthly runs × [input × ((1 − cache share) × input rate + cache share × cached rate) + output × output rate] / 1,000,000.

Cache share is a number between 0 and 1 in the formula. Average usage covers the complete run. For multiple models, calculate each separately and add the totals.

The total budget also includes: seat licences and overage; tool and infrastructure fees; integration and operations; time spent on training, practice and review. We check monthly alert thresholds and enforced spending limits separately.

07 / QUESTIONS FOR LEADERS

Before the rollout,
get the details clear.

Do we need to change tools?

We start with your existing toolchain, including environments that combine several vendors and internal systems. We adapt the workflow and integrations to it. The assessment identifies which connections already exist and which need work.

Can we start with an older, existing product?

Yes, with a clear task whose result can be checked. We map dependencies and business rules, adding tests that capture current behaviour first where necessary. The pilot scope follows the state of the product and its release process.

Is a ChatGPT subscription enough?

It is a useful starting point for an individual trial. For enterprise adoption, we choose a plan based on central access, data handling, administration and billing. API automation running from CI may be a separate cost. Required integrations depend on the existing tools and company policies.

Can AI deploy to production on its own?

We define autonomy for each action during rollout. Initially, AI works in an isolated environment, changes go into a PR, and release follows approval by the designated owner and pipeline checks. Approval rules must also be enforced technically.

How does this work across a large team with several products?

With shared principles and product-specific additions. The platform, repository rules and team support all need owners. Rollout happens in waves; access, training and measurement are part of onboarding every new team.

What if people do not adopt it?

We look at the reason: missing access, unsuitable tasks, no time to practise or unreliable results. Pair work on real tasks and short follow-up sessions help. The value needs to be clear in the person's actual work.

Will we learn prompt engineering?

Prompt tricks get more attention than they deserve. Clear tasks, accessible project context, usable tools and verification matter in day-to-day work. We practise these on the team's code and record useful agreements in project instructions.

How do we know whether it pays off?

The pilot measures total effort and quality. Faster coding is useful when the process also improves after accounting for review, fixes and operations. We use those results to decide whether to continue at a checkpoint agreed in advance.
